## 3. 修改、提交与推送规则

以下规则对本计划后续所有步骤均为强制要求：

1. 每个计划步骤，以及步骤内每个可以独立验收的修改批次，完成代码或文档修改后都必须运行与风险范围相匹配的验证。
2. 验证完成后必须创建独立 Git commit，不得把多个无关修改长期积压在未提交工作区中。
3. 每个 commit 必须及时 push 到当前远端功能分支；只完成本地 commit 不视为该修改完成。
4. push 后必须确认本地 `HEAD` 与对应远端分支提交一致。
5. 只有在验证、commit、push 和远端一致性检查全部完成后，才允许在本计划中把对应步骤或修改批次标记为“已完成”。
6. 每个完成记录必须注明：修改范围、验证结果、分支名称、commit 哈希和 push 状态。
7. 如果验证失败或 push 失败，对应步骤保持“进行中”或“阻塞”，并记录失败原因，不得以跳过测试、弱化断言或只修改计划状态的方式关闭步骤。
8. `outputs/`、测试缓存、字节码和本地日志属于运行产物，不进入 Git commit；设计结果通过运行目录和 `manifest.json` 管理。
